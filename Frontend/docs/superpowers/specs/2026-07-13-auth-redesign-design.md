# UCust — редизайн входа/регистрации: отдельные страницы, легал-хаб, подтверждение по ссылке

**Дата:** 2026-07-13
**Статус:** утверждён к реализации

## Контекст

Сейчас вход и регистрация — модалки (`LoginModal.tsx`, `SignupModal.tsx`) поверх лендинга,
открываются через `useAuthModal()` (контекст `AuthModalProvider.tsx`) и рендерятся в
`ModalShell.tsx` (маленькая карточка на затемнённом фоне, опционально широкий вариант с
брендовым градиентным `aside`).

Пользователь показал референс — экран логина ITMO ID: полноэкранная фотография-фон,
лого сверху слева, карточка формы по центру, без модального затемнения текущей страницы.
По итогам брейншторма (см. диалог) договорились о трёх независимых, но пересекающихся по
файлам изменениях:

1. Вход/регистрация переезжают с модалок на отдельные страницы с полноэкранным фото-фоном.
2. Чекбокс с тремя юр.документами в регистрации становится одним чекбоксом + хаб-страницей
   `/legal`, где перечислены все документы (сейчас 3, дальше будет больше).
3. Шаг подтверждения email (сейчас — 6 полей ввода кода) заменяется на флоу «проверьте
   почту» + переход по ссылке — без реальной отправки писем (в проекте вообще нет бэкенда:
   не найдено ни одного `/api`-роута), это чисто UI-поток на будущее подключение бэкенда.

## Роутинг

| Путь | Назначение |
|---|---|
| `/login` | Новая страница входа (было `LoginModal`) |
| `/signup` | Новая страница регистрации, шаг 1 — форма (было `SignupModal`, step `"form"`) |
| `/signup/verify-email` | Шаг 2 — «Мы отправили ссылку на {email}» (заменяет step `"code"`) |
| `/signup/confirm` | Страница, на которую вела бы ссылка из письма. Открытие всегда показывает успех (нет бэкенда → нет реальной валидации токена) и кнопку «Продолжить» → тот же побочный эффект, что раньше был у «Подтвердить»: `sessionStorage.setItem("uc_show_setup", "1")` + `router.push("/onboarding")` |
| `/legal` | Новая страница-хаб: список всех документов из существующего `LEGAL_LINKS` (`lib/legal.ts`) |

Явного демо-шортката «открыть письмо» на экране `/signup/verify-email` нет (осознанное
решение пользователя) — `/signup/confirm` тестируется прямым переходом по URL.

## Компонент `useAuthModal` — сохраняем публичный API

`Navbar.tsx`, `Hero.tsx`, `Pricing.tsx`, `FinalCta.tsx` вызывают `openLogin()` /
`openSignup()` из контекста и **не меняются**. Меняется только реализация внутри
`AuthModalProvider.tsx`:

```tsx
const router = useRouter();
const value: AuthModalContextValue = {
  openLogin: () => router.push("/login"),
  openSignup: () => router.push("/signup"),
  close: () => {},
};
```

Провайдер перестаёт рендерить `<LoginModal>`/`<SignupModal>` — они удаляются как модалки
(логика переезжает в новые страницы, см. ниже). `close` остаётся в интерфейсе как no-op,
чтобы не ломать типы у мест, которые его импортируют (проверить перед удалением —
по грепу выше `close` нигде не вызывается за пределами провайдера, но интерфейс не трогаем
ради минимального диффа).

## Визуал auth-страниц

Общий layout-компонент (например `components/auth/AuthPageChrome.tsx`), переиспользуется
в `/login`, `/signup`, `/signup/verify-email`, `/signup/confirm`:

- Фон на весь вьюпорт — `/backgrounds/bg-6.jpg` («Мраморные волны», уже используется как
  один из 8 фонов дашборда в `lib/dashboard/appearance.ts`), `fixed`, `object-cover`.
- Поверх фона — фиксированный тёмный scrim-градиент (не зависит от `.dark`/светлой темы
  сайта — как в референсе ITMO ID, где фон-фото один и тот же вне зависимости от темы):
  плотнее снизу и по краям, мягче в центре, чтобы лого и карточка читались.
- Лого UCust (белый вариант, как на `/legal` в тёмной теме — `brand/logo-lighttext.webp`)
  фиксированно в левом верхнем углу, ссылка на `/`.
- Небольшая ссылка «На главную» (по образцу `app/legal/layout.tsx`) — крестик/стрелка
  рядом с лого или в углу карточки формы.
- Карточка формы — по центру (на десктопе может быть смещена к правой трети, как на
  референсе, финальное позиционирование — на усмотрение при вёрстке), сохраняет
  `bg-card`, `rounded-[28px]`, `shadow-lift` и все текущие `dark:`-варианты полей/кнопок
  один в один как в сегодняшних `LoginModal`/`SignupModal` — меняется только то, что
  снаружи карточки (фон), не то, что внутри неё.
- `ModalShell.tsx` не трогаем (используется другими модалками в проекте — тарифы, легал
  и т.д., не только auth).

## Содержимое страниц

**`/login`** — переносим содержимое `LoginModal.tsx` как есть (email/пароль, «запомнить
меня», «забыли пароль», кнопки VK/Яндекс через `seedDemoProject()` + редирект в
`/dashboard`, ссылка «Нет аккаунта? Зарегистрироваться» → `<Link href="/signup">`).

**`/signup`** — переносим содержимое step `"form"` из `SignupModal.tsx` как есть (Имя/
Фамилия/Отчество/Email/Пароли), с двумя изменениями:
1. Чекбокс: было 3 ссылки (`/legal/offer`, `/legal/privacy`, `/legal/pdn-consent`) в одной
   строке → один чекбокс: «Я принимаю [условия использования]», ссылка ведёт на `/legal`.
2. Сабмит вместо `setStep("code")` делает `router.push("/signup/verify-email")` (можно
   передать email через query-параметр или временный `sessionStorage`, чтобы следующий
   экран мог показать адрес — решение по вкусу при реализации).

**`/signup/verify-email`** — новый экран (заменяет step `"code"`):
- Заголовок «Проверьте почту», текст «Мы отправили ссылку для подтверждения на {email}»
  (или без интерполяции email, если не прокидывали).
- Кнопка «Отправить письмо ещё раз» — визуальная, без реального действия (как и сегодняшний
  «Отправить ещё раз» ничего не делал).
- Ссылка «← Изменить email» → `router.push("/signup")`.
- Без демо-кнопки «открыть письмо».

**`/signup/confirm`** — новый экран:
- Заголовок «Почта подтверждена» + кнопка «Продолжить», которая выполняет прежний
  `handleConfirm`: `sessionStorage.setItem("uc_show_setup", "1")` → `router.push("/onboarding")`.
- Доступен только прямым переходом по URL (не связан ссылкой из `/signup/verify-email`).

**`/legal`** (новый файл `app/legal/page.tsx`, использует уже существующий
`app/legal/layout.tsx`) — простой список из `LEGAL_LINKS` (`lib/legal.ts`), без выдумывания
новой структуры данных. Существующие 3 документа (`offer`, `privacy`, `pdn-consent`)
остаются доступны по своим адресам `/legal/[slug]` без изменений.

## Вне объёма (сознательно)

- Реальная отправка email / генерация и валидация токена подтверждения — бэкенда в проекте
  нет вообще; весь флоу выше остаётся мокапом до появления бэкенда.
- Ссылки на юр.документы в футере (`Footer.tsx`) и в меню профиля дашборда — используют
  `LEGAL_LINKS` по отдельности и не меняются; консолидация в один чекбокс касается только
  формы регистрации.
- `ModalShell`, `TariffConfigurator`, другие модалки на `useAuthModal`/`ModalShell` — не
  затрагиваются.
- Анимированные переходы между auth-страницами (page transitions) — обычная навигация
  Next.js, без кастомной анимации смены страниц (в отличие от исчезающей/появляющейся
  модалки сегодня).

## Приёмка

- Клик «Войти»/«Зарегистрироваться» из шапки, hero, pricing, FinalCta ведёт на `/login`/
  `/signup` (полноэкранная фото-страница), а не на модалку.
- Форма регистрации по сабмиту ведёт на `/signup/verify-email`, оттуда прямой переход на
  `/signup/confirm` показывает успех и ведёт в `/onboarding` с тем же побочным эффектом,
  что раньше (сохраняется трекер настройки на дашборде).
- Чекбокс регистрации — один пункт, ссылка ведёт на `/legal`, где видны все 3 существующих
  документа.
- Фон одинаковый (`bg-6.jpg` + scrim) на `/login`, `/signup`, `/signup/verify-email`,
  `/signup/confirm`, не зависит от `.dark`.
- Другие модалки в проекте (тарифы и т.п.) продолжают работать через `ModalShell` без
  изменений.
