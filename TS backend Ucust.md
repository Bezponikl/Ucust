# ТЕХНИЧЕСКОЕ ЗАДАНИЕ ДЛЯ БЭКЕНД-РАЗРАБОТЧИКА
## Проект: UCust - AI-Ассистент Персонального Маркетолога

---

## 1. О ПРОЕКТЕ

UCust - это SaaS-платформа, которая помогает владельцам малого бизнеса (кафе, салоны красоты, магазины, сервисы) автоматизировать маркетинг с помощью искусственного интеллекта. Платформа генерирует контент для соцсетей, управляет акциями, собирает и отвечает на отзывы, а также предоставляет чат-бота для общения с клиентами 24/7.

**Целевая аудитория:** владельцы малого бизнеса в России, маркетологи МСБ, предприниматели.

**Валюта:** рубли (RUB).

**Язык интерфейса:** русский.

## 2. ПОЛЬЗОВАТЕЛИ И АВТОРИЗАЦИЯ

### 2.1 Регистрация

Пользователь регистрируется через форму: имя, email, пароль, подтверждение пароля. Также должна быть возможность регистрации через Яндекс ID (OAuth 2.0). После регистрации пользователь попадает на онбординг, где создает свой первый проект (бизнес).

Что нужно реализовать:
- Хеширование паролей (bcrypt)
- Подтверждение email (отправка письма со ссылкой)
- OAuth 2.0 интеграция с Яндекс ID
- JWT-токены для сессий (access token + refresh token)
- Защита от брутфорса: ограничение попыток входа (максимум 5 за 15 минут)

### 2.2 Авторизация

Вход по email + пароль или через Яндекс. Есть чекбокс "Запомнить меня" - если включен, refresh token живет 30 дней, если нет - 24 часа. Access token живет 15 минут в любом случае.

### 2.3 Восстановление пароля (6-ти значный)

Пользователь вводит email, получает письмо с кодом для сброса пароля. Код действителен 15 минут. 

### Восстановление пароля (6-ти значный)
Пользователь вводит email, получает письмо с кодом для сброса пароля. Код действителен 15 минут. 
### 2.4 Роли

На первом этапе роль одна - владелец аккаунта. В будущем планируется командная работа с ролями (администратор, редактор, наблюдатель), но сейчас это не нужно. Однако архитектуру базы данных лучше сразу заложить с учетом ролей.

## 3. ПРОЕКТЫ (БИЗНЕСЫ)

Каждый пользователь может создать несколько проектов. Проект = один бизнес. Количество проектов ограничено тарифным планом (1 / 1/ от 3).

### 3.1 Создание проекта

При создании проекта пользователь заполняет:
- Название бизнеса (обязательно)
- Сфера деятельности: кафе/ресторан, салон красоты, розничная торговля, услуги, образование, фитнес, медицина, другое (обязательно)
- Город (обязательно)
- Описание бизнеса (необязательно)
- Целевая аудитория: текстовое описание (необязательно)
- Tone of voice: дружелюбный / профессиональный / неформальный / креативный (обязательно)
- Подключение соцсетей: VK, Telegram, MAX - на первом этапе просто сохраняем ссылки на аккаунты, реальная интеграция с API соцсетей - отдельная задача на будущее
- Время работы бизнеса: время открытия, время закрытия, выходные дни
- Логотип бизнеса (загрузка изображения)

### 3.2 Переключение между проектами

В хедере дашборда есть дропдаун для переключения между проектами. При переключении все данные (контент-план, акции, отзывы, статистика) меняются на данные выбранного проекта.

### 3.3 Редактирование и удаление

Пользователь может редактировать все параметры проекта в настройках, а также удалить проект (с подтверждением). При удалении все связанные данные удаляются каскадно.

## 4. КОНТЕНТ-ПЛАН

Это ядро платформы. Пользователь видит календарь на месяц, в котором расположены посты для соцсетей.

### 4.1 Генерация контент-плана

При первом создании проекта (или по запросу пользователя) AI должен сгенерировать контент-план на месяц. На вход AI получает:
- Сферу деятельности бизнеса
- Описание бизнеса
- Целевую аудиторию
- Tone of voice
- Город (для локальных событий)
- Текущий месяц и год

На выходе AI должен вернуть набор постов (примерно 15-30 на месяц), каждый из которых содержит:
- Дату и время публикации
- Текст поста
- Рекомендуемые хештеги
- Для каких соцсетей предназначен (VK, Telegram, MAX)
- Тип контента: информационный, продающий, развлекательный, обучающий

### 4.2 Структура поста

Каждый пост в системе имеет:
- Текст (обязательно)
- Изображение (генерируется AI или загружается пользователем)
- Хештеги (список)
- Целевые соцсети (массив)
- Дата и время публикации
- Статус: черновик / запланирован / опубликован / ошибка публикации
- Тип контента: пост / видео
- Статистика (после публикации): просмотры, лайки, комментарии, репосты

### 4.3 Действия с постами

Пользователь может:
- Создать пост вручную (заполнив все поля)
- Отредактировать существующий пост (текст, изображение, хештеги, дату)
- Удалить пост
- Дублировать пост (создать копию с возможностью изменений)
- Перенести пост на другую дату (drag & drop на фронте, на бэке - обновление даты)
- Опубликовать пост сейчас (немедленная публикация)
- Поставить на паузу запланированный пост

### 4.4 Видеоконтент в контент-плане

Пользователь может добавить видео в контент-план:
- Загрузить видеофайл (до 500 МБ)
- Указать описание и хештеги
- Выбрать платформы (YouTube, VK Видео, Telegram)
- Автоматическое определение длительности видео

Хранение видео - через облачное хранилище (S3-совместимое).

## 5. ГЕНЕРАЦИЯ КОНТЕНТА (AI)

Это три отдельные функции, каждая со своей страницей на фронте.

### 5.1 Генерация поста

Пользователь заполняет форму:
- Тема поста (текст, обязательно)
- Тон общения: дружелюбный / профессиональный / неформальный / продающий
- Длина: короткий (до 100 символов) / средний (100-300) / длинный (300+)
- Платформы: VK, Telegram, Instagram, Facebook
- Флаги: добавить хештеги, добавить emoji, добавить призыв к действию

Бэкенд должен:
1. Принять параметры от фронта
2. Сформировать промпт для AI (LLM), включив контекст бизнеса из проекта
3. Отправить запрос к AI API (OpenAI / YandexGPT / другая модель)
4. Сгенерировать изображение для поста через AI (DALL-E / Kandinsky / другой генератор)
5. Вернуть результат: текст + изображение + хештеги
6. Сохранить результат как черновик

Пользователь может:
- Перегенерировать (новый запрос с теми же параметрами)
- Отредактировать результат
- Добавить в контент-план (выбрать дату)
- Опубликовать сразу

### 5.2 Генерация видео

Пользователь заполняет:
- Тема видео (текст)
- Длительность: 15 сек / 30 сек / 1 мин / 2-3 мин
- Формат: вертикальный (9:16) / квадратный (1:1) / горизонтальный (16:9)
- Стиль: динамичный / спокойный / презентационный / storytelling
- Музыка: без музыки / энергичная / фоновая / расслабляющая
- Платформы: YouTube, VK Видео, Telegram, Instagram Reels

На первом этапе бэкенд генерирует только описание и раскадровку (сценарий) для видео через текстовую AI-модель. Реальная генерация видео через AI (Runway, Sora и т.д.) - это следующий этап. Но API-эндпоинт должен быть спроектирован так, чтобы потом легко подключить видеогенерацию.

Результат:
- Текстовое описание видео
- Покадровый план (сценарий)
- Рекомендуемые параметры (длительность, формат)
- Описание для публикации + хештеги

### 5.3 Генерация сценария для видео

Пользователь заполняет:
- Тема (текст)
- Длительность видео: 30 сек / 1 мин / 2-3 мин / 5+ мин
- Стиль подачи: обучающий / развлекательный / продающий / информационный
- Целевая аудитория: широкая / молодежь (18-25) / взрослые (25-45) / профессионалы
- Призыв к действию: текст CTA (опционально)

AI генерирует покадровый сценарий:
- Разбивка по секундам/минутам
- Описание каждой сцены: что в кадре, текст на экране, закадровый текст
- Вступление, основная часть, призыв к действию, концовка

Пользователь может перегенерировать, отредактировать, скачать в PDF, отправить на email.

### 5.4 Общие требования к AI-генерации

- Все промпты должны учитывать контекст бизнеса: сфера, tone of voice, целевая аудитория, город
- Нужно хранить историю генераций (что генерировалось, с какими параметрами, какой результат)
- Rate limiting: ограничение количества генераций в зависимости от тарифа
- Таймаут запросов к AI: максимум 30 секунд, при превышении - вернуть ошибку
- Поддержка streaming (потоковой передачи) для текстовой генерации - пользователь видит, как текст появляется постепенно

## 6. АКЦИИ И ПРОМО

### 6.1 Автоматические рекомендации

Система должна автоматически предлагать акции на основе:
- Календаря праздников и событий (база из 180+ дат на 2026-2027 годы: государственные праздники, профессиональные праздники, городские события, международные дни)
- Сферы бизнеса (для кафе - день кофе, для салонов - день красоты и т.д.)
- Города пользователя (день города, местные события)
- Истории прошлых акций (не предлагать повторы)

Рекомендации должны показываться заранее (за 3-14 дней до события) с предложением запустить акцию.

### 6.2 Однокнопочный запуск

Это ключевая функция. Пользователь нажимает одну кнопку, и система:
1. Выбирает ближайшее подходящее событие из календаря
2. Генерирует текст акции через AI
3. Генерирует изображение для поста-акции
4. Формирует готовый пост с условиями акции
5. Возвращает превью пользователю

Пользователь видит готовый пост и может опубликовать? внести в контент-план или перегенерировать.

### 6.3 Ручное создание акции

Пользователь заполняет:
- Повод для акции (текст)
- Что предлагает (скидка, подарок, бонус - текст)
- Длительность: 1 день / 3 дня / неделя / 2 недели / месяц
- Дополнительные детали (текст, опционально)

Бэкенд генерирует пост-акцию через AI на основе этих данных + контекст бизнеса.

### 6.4 Управление акциями

Каждая акция имеет:
- Название
- Описание и условия
- Даты начала и окончания
- Связанный пост (изображение + текст)
- Статус: черновик / активна / завершена / отменена
- Статистика: количество участников, охват, ROI, вовлеченность

Пользователь может: запустить, остановить, редактировать, дублировать, удалить акцию.

### 6.5 Календарь событий

Нужна таблица в базе данных с праздниками и событиями (180+ записей). Каждое событие:
- Название
- Дата (может быть плавающей, например "последняя пятница ноября")
- Тип: государственный праздник / профессиональный / международный / городской / бизнес-событие
- Применимые сферы бизнеса (массив)
- Город (если локальное) или null (если общее)

API должен возвращать события за указанный период с фильтрацией по сфере и городу.

## 7. УПРАВЛЕНИЕ ОТЗЫВАМИ

### 7.1 Сбор отзывов

На первом этапе отзывы добавляются вручную или импортируются. В будущем планируется автоматический парсинг с площадок, но сейчас это не в скоупе.

Каждый отзыв содержит:
- Имя автора
- Текст отзыва
- Рейтинг (1-5 звезд)
- Платформа-источник: Google, Яндекс, 2GIS, VK, Instagram, свой сайт
- Дата отзыва
- Статус ответа: без ответа / ответ отправлен / черновик ответа
- Тональность: положительный / нейтральный / негативный (определяется AI автоматически)

### 7.2 AI-анализ отзывов

По запросу пользователя (кнопка "Анализировать") бэкенд должен:
1. Собрать все отзывы за выбранный период
2. Отправить в AI для анализа
3. Вернуть:
   - Общую тональность (процент положительных / нейтральных / негативных)
   - Ключевые темы, которые хвалят (с количеством упоминаний)
   - Ключевые проблемы (с количеством упоминаний)
   - Рекомендации по улучшению (текстовые)

Результаты анализа кешируются и обновляются только при нажатии "Анализировать" или при добавлении новых отзывов.

### 7.3 Генерация ответов на отзывы

Пользователь нажимает "Сгенерировать ответ AI" на конкретном отзыве. Бэкенд:
1. Берет текст отзыва, рейтинг, тональность
2. Учитывает tone of voice бизнеса
3. Генерирует 3 варианта ответа через AI
4. Возвращает варианты пользователю

Пользователь выбирает вариант, может отредактировать и сохранить (как черновик или как финальный ответ).

## 8. ЧАТ-БОТ

### 8.1 Настройки чат-бота

Для каждого проекта создается свой чат-бот с параметрами:
- Имя бота
- Приветственное сообщение
- Тон общения: дружелюбный / официальный / профессиональный
- Часы работы автоответов (время начала и окончания)
- Статус: включен / выключен

### 8.2 База знаний

Пользователь создает пары "вопрос - ответ" для обучения бота:
- Часы работы? -> "Мы работаем с 9:00 до 21:00 каждый день"
- Как сделать заказ? -> "Вы можете оформить заказ на нашем сайте..."
- И так далее

Также можно импортировать базу знаний из текстового файла.

Бот использует базу знаний как приоритетный источник. Если вопрос не покрывается базой знаний - бот генерирует ответ через AI с учетом контекста бизнеса.

### 8.3 Интеграции с мессенджерами

На первом этапе нужно подготовить архитектуру для подключения:
- Telegram Bot API
- VK Bot API
- WhatsApp Business API
- Instagram Direct API

Реализация на первом этапе - только Telegram (как самый простой для интеграции). Остальные - в следующих итерациях.

Для Telegram:
- Пользователь указывает токен бота
- Бэкенд настраивает webhook
- Входящие сообщения обрабатываются: сначала ищем ответ в базе знаний, потом через AI
- Все диалоги сохраняются в базе

### 8.4 История диалогов

Каждый диалог сохраняется:
- Имя клиента (если доступно)
- Мессенджер-источник
- Все сообщения (от клиента и от бота)
- Время каждого сообщения
- Статус: решено автоматически / требует внимания / в процессе
- Был ли ответ от оператора (ручной) или от бота (автоматический)

Пользователь может:
- Просматривать историю диалогов
- Отвечать вручную через интерфейс (сообщение отправляется обратно в мессенджер)
- Пометить диалог как "решено"

### 8.5 Статистика чат-бота

- Количество диалогов за день / неделю / месяц
- Процент автоматически решенных вопросов
- Среднее время ответа
- Самые частые вопросы

## 9. УВЕДОМЛЕНИЯ

### 9.1 Типы уведомлений

Система генерирует уведомления при следующих событиях:
- **Контент:** пост опубликован, пост запланирован, ошибка публикации, контент-план сгенерирован
- **Акции:** акция запущена, акция завершена, рекомендация новой акции
- **Отзывы:** новый отзыв получен, негативный отзыв (приоритетное), ответ на отзыв отправлен
- **Чат-бот:** вопрос без ответа (бот не справился), критичный вопрос (требует внимания оператора)
- **Система:** оплата прошла, оплата не прошла, тариф истекает, лимит постов почти исчерпан

### 9.2 Структура уведомления

- Заголовок
- Полный текст
- Тип (контент / акции / отзывы / чат-бот / система)
- Статус: прочитано / не прочитано
- Дата и время
- Ссылка на связанный объект (пост, отзыв, диалог и т.д.)

### 9.3 Доставка

- В приложении (обязательно): попап в хедере + страница всех уведомлений
- Email (опционально, настраивается пользователем в настройках)
- Push (на будущее, заложить архитектуру)

### 9.4 API

- Получить список уведомлений (с пагинацией, фильтрацией по типу и статусу)
- Получить количество непрочитанных
- Отметить одно уведомление как прочитанное
- Отметить все как прочитанные
- Удалить уведомление
- Получить полный текст одного уведомления

### 10.2 Платежная система

Интеграция с ЮKassa (Яндекс Касса) для приема платежей в рублях:
- Подписка с автоматическим продлением (рекуррентные платежи)
- Привязка банковской карты
- Чеки по 54-ФЗ (онлайн-кассы)
- Возврат средств (гарантия 30 дней)

### 10.3 Что нужно реализовать

- Создание подписки при выборе тарифа
- Автоматическое списание при продлении
- Смена тарифа (повышение - сразу, понижение - с начала следующего периода)
- Отмена подписки (доступ до конца оплаченного периода)
- История платежей (дата, сумма, статус, ссылка на чек)
- Проверка лимитов (количество проектов, постов, AI-генераций) перед каждым действием
- Уведомление за 3 дня до списания
- Уведомление при неудачном списании (повторная попытка через 3 дня)

### 10.4 Пробный период

7 дней бесплатного доступа к тарифу "Рост" при первой регистрации. Без привязки карты. По истечении - блокировка функционала с предложением выбрать тариф.

## 15. ФОНОВЫЕ ЗАДАЧИ

Нужен планировщик задач (cron) для:

1. **Публикация постов** - каждую минуту проверять, есть ли посты со статусом "запланирован" и временем публикации в прошлом. Если есть - публиковать (когда будет интеграция с соцсетями) или менять статус на "опубликован".

2. **Напоминания об акциях** - раз в день проверять календарь событий и создавать рекомендации для пользователей (за 3-14 дней до события).

3. **Завершение акций** - раз в час проверять активные акции с истекшей датой окончания и менять статус на "завершена".

4. **Биллинг** - раз в день проверять подписки с истекающим сроком и инициировать списание.

5. **Очистка** - раз в неделю удалять неподтвержденные аккаунты старше 7 дней, истекшие токены сброса пароля, старые уведомления (старше 90 дней).

6. **Еженедельный отчет** - раз в неделю формировать и отправлять email с ключевой статистикой (для пользователей, которые включили эту опцию).

## 16. БЕЗОПАСНОСТЬ

### 16.1 Обязательные требования

- Все пароли хешируются bcrypt с salt rounds >= 12
- JWT access token: срок жизни 15 минут, хранится в памяти (не в localStorage)
- JWT refresh token: httpOnly cookie, secure, sameSite: strict
- Все API-эндпоинты требуют аутентификации (кроме публичных: регистрация, вход, лендинг)
- Проверка прав: пользователь может работать только со своими проектами и данными
- Rate limiting: 100 запросов в минуту на пользователя, 5 попыток входа за 15 минут
- CORS: разрешить только домен приложения
- Валидация всех входящих данных (типы, длина, формат)
- Параметризованные SQL-запросы (никаких строковых конкатенаций)
- Санитизация пользовательского ввода (XSS-защита)
- HTTPS обязательно

### 16.2 Логирование

- Все действия пользователя (вход, выход, создание/удаление объектов)
- Ошибки и исключения
- Запросы к AI API (без содержимого ответа, только метаданные)
- Платежные операции

## 17. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА

### 17.1 Рекомендуемый стек

- **База данных:** PostgreSQL (основная) + Redis (кеширование, сессии, очереди)
- **ORM:** Prisma/ Hibernate
- **Очереди задач:** BullMQ
- **Хранилище файлов:** Yandex Object Storage (S3-совместимое)
- **Платежи:** ЮKassa API
- **Email:** Nodemailer + SMTP Yandex
- **Деплой:** Docker + Docker Compose,

### 17.2 Структура API

REST API с JSON. Документация через Swagger/OpenAPI. Версионирование: /api/v1/...

Формат ответов:
- Успех: { "success": true, "data": { ... } }
- Ошибка: { "success": false, "error": { "code": "VALIDATION_ERROR", "message": "..." } }
- Пагинация: { "data": [...], "pagination": { "page": 1, "limit": 20, "total": 150 } }

8. **promotion_stats** - статистика акций (id, promotion_id, participants, reach, roi, engagement)

6. Чат-бот работает через Telegram
