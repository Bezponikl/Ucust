# Дашборд — дизайн (итерация 1: шелл + обзор)

Дата: 2026-06-28
Статус: утверждён к реализации

## Цель

Рабочее пространство, куда пользователь попадает после онбординга. Итерация 1 строит
**адаптивный шелл навигации** и **главный экран «Дашборд» (обзор состояния бизнеса)**.
Остальные разделы — routed-заглушки «Скоро», разрабатываются отдельными итерациями.

Главный сценарий (второй визит, утро): человек хочет сначала **увидеть статистику/аналитику**,
затем **контент-план**. Поэтому обзор открывается сводкой аналитики, календарь — превью.

## Природа и скоуп

- **Гибрид: моки сейчас, API потом** (как в онбординге). Чистый слой данных `lib/dashboard/`.
- **Мобайл-фёрст:** 60% аудитории предпочитают мобильную версию (+ в планах APK через
  Capacitor). Шелл обязан быть удобным на мобиле.
- **Итерация 1:** адаптивный шелл + обзорный экран. Разделы Контент/Акции/Отзывы/Чат-бот —
  заглушки.
- **Вне скоупа:** реальные данные/бэкенд, полноценные разделы, реальное создание/переключение
  проектов, **экран создания одиночного поста** (отдельная функция тарифа от 3500 — отдельная
  будущая итерация), полный календарь и детальная аналитика (будущие итерации).

## Архитектура

### Роуты (App Router)

```
app/dashboard/layout.tsx          — DashboardShell (топ-бар + сайдбар/bottom-nav) + DashboardProvider
app/dashboard/page.tsx            — обзор (заменяет текущую заглушку app/dashboard/page.tsx)
app/dashboard/content/page.tsx    — заглушка «Скоро» (Контент/Календарь)
app/dashboard/promos/page.tsx     — заглушка «Скоро» (Акции)
app/dashboard/reviews/page.tsx    — заглушка «Скоро» (Отзывы)
app/dashboard/chatbot/page.tsx    — заглушка «Скоро» (Чат-бот)
app/dashboard/create/page.tsx     — заглушка «Скоро» (Создать контент — будущая итерация)
```

### Шелл (адаптивный)

`DashboardShell` оборачивает контент разделов:
- **Топ-бар** (`DashboardTopBar`): лого (свап по теме) · **переключатель проекта** ▾
  (имя проекта из онбординга + список мок-проектов + «Добавить проект»; декоративный) ·
  `ThemeToggle` · колокольчик с бейджем · аватар+имя.
- **Десктоп (lg+):** левый **сайдбар** (`DashboardSidebar`) с 5 пунктами, активное состояние.
- **Мобайл (<lg):** сайдбар скрыт, внизу — **bottom nav** (`DashboardBottomNav`) с теми же
  5 пунктами (иконка+подпись), фиксированная, активное состояние, безопасные отступы.

Пункты навигации (ровно 5, под bottom nav):
**Дашборд** (`/dashboard`) · **Контент** (`/dashboard/content`) · **Акции** (`/dashboard/promos`) ·
**Отзывы** (`/dashboard/reviews`) · **Чат-бот** (`/dashboard/chatbot`).
Активный пункт — по `usePathname()`.

### Данные

`DashboardProvider` (контекст): читает «мозг бренда» из `sessionStorage` (ключ `ucust:onboarding`,
тот же, что у онбординга) и собирает данные обзора через `getDashboardData(profile)`. Если
профиля нет (прямой заход) — дефолтные данные с именем «Ваш бизнес». Флаг `hydrated` как в
онбординге (избегаем мерцания/неверных значений до чтения storage).

```
lib/dashboard/types.ts   — DashboardData, Stat, ChartSeries, AiTip, PlanDay, ActivityItem
lib/dashboard/mock.ts     — getDashboardData(profile: BrandProfile | null): DashboardData
```

`getDashboardData` приправляет данные нишей профиля (имя в приветствии; рекомендации/контент
в духе ниши через поля профиля). Возвращает синхронно (данные локальные). Позже — замена на
fetch без правок UI.

## Главный экран «Дашборд» (обзор)

Одна колонка на мобиле, многоколоночные сетки на десктопе. Порядок блоков (под приоритет
«аналитика → контент-план»):

1. **Приветствие** (`OverviewHeader`): «Добрый день!» + название бизнеса, подзаголовок
   «Вот что происходит с вашим бизнесом», кнопка **«Создать контент»** (`.btn-glass-blue`)
   → `/dashboard/create` (заглушка).
2. **Стат-карты** (`StatCards`): 4 карты — **Просмотры · Вовлечённость · Новые подписчики ·
   Отзывы**. Каждая: иконка (мягкий цветной фон палитры), значение, подпись, период/дельта.
   Сетка: 2×2 мобайл, 4 в ряд десктоп.
3. **График** (`ReachChart`): «Охват за последние 30 дней», табы **Охват / Вовлечённость /
   Клики** (переключают серию). Лёгкий **SVG-линейный график без сторонних библиотек**
   (полилиния + сетка + подписи осей). Уважает reduced-motion.
4. **Рекомендации AI** (`AiTips`): 3 карточки-подсказки (цветная точка-приоритет, заголовок,
   текст, кнопка «Перейти»). Примеры в духе ниши: «Создать пост о…», «Ответить на N отзывов»,
   «Запустить акцию…». «Перейти» → соответствующий раздел-заглушка.
5. **Контент-план — превью** (`WeekPreview`): лента 7 дней (день недели + число + статус-точка
   Опубликован/Запланирован/Черновик + иконки каналов VK/TG из `lib/channels`); ссылка
   **«Все посты →»** → `/dashboard/content`. На мобиле — горизонтальный скролл.
6. **Недавняя активность** (`ActivityFeed`): лента событий (опубликован пост, новый отзыв,
   запущена акция) с временем и мягким цветным маркером.

Легенда статусов: Опубликован — `success`, Запланирован — `brand`, Черновик — `ink-muted`.

## Заглушки разделов

`SectionStub` (переиспользуемый): иконка раздела, заголовок, «Раздел в разработке — появится
в ближайшем обновлении», в рамках шелла (топ-бар + навигация сохраняются). Используется на
`/dashboard/{content,promos,reviews,chatbot,create}`.

## Стилистика

Бренд-синий + палитра (purple/pink/orange/success) для акцентов стат-карт, AI-подсказок,
статус-точек. Скругления карточек `rounded-[20px]`/`rounded-[24px]`. Мягкие цветные фоны
иконок (`bg-brand-tint`, `bg-success/15` и т.п.). Никаких насыщенных тёмных плашек в light.

## Мобайл-фёрст требования

- Контент обзора — одна колонка; стат-карты 2×2; график на всю ширину; неделя — горизонтальный
  скролл; AI-подсказки — стопка.
- Bottom nav фиксирован снизу, контент имеет нижний отступ, чтобы не перекрываться.
- Тач-цели ≥ 44px; переключатель проекта и аватар-меню удобны пальцем.

## Доступность

- Навигация: `aria-current="page"` на активном пункте (sidebar и bottom nav).
- Табы графика: `role="tablist"`, переключение с клавиатуры.
- Иконки декоративные — `aria-hidden`; значения карт — с текстовыми подписями.
- Анимации уважают `prefers-reduced-motion` (mounted-паттерн, без ветвления до гидрации).
