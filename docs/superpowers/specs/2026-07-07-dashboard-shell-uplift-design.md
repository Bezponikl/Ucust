# Апгрейд шелла дашборда до уровня B2B SaaS

**Дата:** 2026-07-07
**Статус:** дизайн утверждён, готов к плану реализации

## Контекст

Мы редизайним ЮКаст под визуальный язык Postiz (крупные цветные панели с «живой»
анимацией продукта внутри). Ключевой вывод обсуждения: чтобы такие карточки
выглядели дорого, сперва нужно поднять **сам внутренний интерфейс** (дашборд и
экраны продукта) до уровня современного B2B SaaS — эти же экраны потом
переиспользуются в лендинг-панелях.

Референсы визуального уровня — тёмные полированные экраны, «плавающие» панели,
AI-ассистент, аватары с бейджами соцсетей (гифки из обсуждения).

Не трогаем: Hero (переливающийся градиент), навбар лендинга, футер лендинга.
Сохраняем наш стиль — шрифт Manrope, скругления, палитра.

## Декомпозиция (общая картина)

- **A. Апгрейд внутреннего интерфейса до B2B SaaS.** Дашборд-шелл + экраны
  (Обзор, Создание, Контент/Календарь, Аналитика, Отзывы, Чат/Инбокс).
  Дробится на слайсы.
  - **A1 (ЭТОТ СПЕК). Модернизация шелла дашборда.**
  - A2+. Экраны по одному/группами — отдельные спеки.
- **B. Лендинг в Postiz-стиле** — цветные панели с живыми экранами внутри
  (Features → панели; затем HowItWorks, Channels, Reviews, Pricing, FAQ,
  ProductShowcase). Отдельные спеки.

Этот документ описывает **только A1**.

## Цель A1

Поднять каркас дашборда (топбар, сайдбар, нижняя навигация, рабочая зона) до
современного B2B SaaS: чёткая иерархия навигации, аккуратные активные состояния,
единый заголовок страниц, стандартные примитивы карточки и отступов, мягкий
motion, премиальная тёмная тема. Каркас должен стать «набором кубиков», из
которого дальше собираются экраны (слайсы A2+).

## Не-цели (YAGNI)

- Сворачивание сайдбара в icon-rail — не делаем.
- Рабочая логика поиска / командная строка ⌘K — не добавляем (даже визуально).
- Переработка контента самих экранов (Обзор, Контент и т.д.) — это A2+.
- Новые бренд-цвета — не вводим. Палитра: синий `#4f7dff` (насыщенный `#1a5bff`),
  фиолетовый `#7b5cff`, розовый `#ff5fa2`. Токены уже в `app/globals.css`.
- Изменение роутинга и состава пунктов навигации.

## Текущее состояние (отправная точка)

- `components/dashboard/DashboardShell.tsx` — раскладка: топбар, контейнер
  (сайдбар + `<main>`), футер, bottom-nav, SetupTracker, Toaster.
- `DashboardTopBar.tsx` — стеклянная карточка-шапка: логотип, ProjectSwitcher,
  ThemeToggle, уведомления, ProfileMenu.
- `DashboardSidebar.tsx` — sticky стеклянная панель, плоский список `NAV_ITEMS`,
  активный пункт = `bg-brand-tint text-brand`.
- `DashboardBottomNav.tsx` — мобильная стеклянная пилюля с теми же пунктами.
- `dashboard/nav` — источник `NAV_ITEMS` + `isNavActive`.

Каркас уже стеклянный и опрятный. Задача A1 — эволюция, не переписывание с нуля.

## Дизайн A1

### 1. Сайдбар (desktop)

- **Primary-CTA «Создать» вверху** панели: крупная заметная кнопка (бренд-заливка),
  ведёт на `/dashboard/create`. Всегда первый элемент.
- **Группировка навигации** по разделам с тонкими подписями-лейблами
  (uppercase, приглушённый). Предполагаемые группы (состав пунктов берём из
  текущего `NAV_ITEMS`, не добавляя новых):
  - «Работа»: Обзор, Создать, Контент.
  - «Рост»: Аналитика, Акции, Отзывы, Чат-бот/Инбокс.
  - «Настройки»: Бизнес, Аккаунт (если присутствуют в NAV_ITEMS).
  Точное распределение фиксируется при реализации по факту содержимого `nav`.
- **Активный пункт**: заливка-пилюля + левый акцент-индикатор (полоска/точка
  бренд-цвета), плавные переходы hover/active.
- **Воркспейс-карточка внизу** панели: текущий тариф + прогресс использования
  (напр. «18/30 постов», прогресс-бар) + кнопка апгрейда. Данные — из
  `lib/dashboard` (при отсутствии поля используем разумную заглушку, помеченную
  TODO, без выдумывания API).

### 2. Топбар

- Состав сохраняем: логотип, ProjectSwitcher, ThemeToggle, уведомления,
  ProfileMenu. Поиск НЕ добавляем.
- Наводим ритм: выравнивание, единые размеры кнопок-иконок, консистентные
  hover-состояния.
- Контекстный заголовок страницы в топбаре — **не делаем** здесь; заголовок
  живёт в `PageHeader` рабочей зоны (см. ниже), чтобы не дублировать.

### 3. Рабочая зона + примитивы

- Новый компонент **`PageHeader`** (`components/dashboard/PageHeader.tsx`):
  заголовок + опциональный подзаголовок + слот primary-действия справа.
  Переиспользуется всеми экранами (в A1 подключаем на существующих страницах
  без изменения их контента — только шапка).
- **Примитив карточки**: опираемся на существующий `.bento-card` /
  `components/dashboard/settings/primitives.tsx`; при необходимости вводим
  единый `Card` в dashboard-примитивах. Не плодим дубли — сперва проверяем,
  что уже есть.
- **Шкала отступов и ритм секций**: фиксируем единые значения (gap между
  секциями, padding карточек) и применяем в шелле; экраны подтянутся в A2+.

### 4. Motion

- Мягкий mount-переход контента рабочей зоны при смене маршрута
  (framer-motion, лёгкий fade/rise, короткий).
- Плавные hover/active в навигации (уже частично есть — унифицируем).
- Полное уважение `prefers-reduced-motion`: все переходы отключаются/замирают
  (в проекте уже есть глобальное правило reduced-motion в `globals.css`).

### 5. Темы

- Работает в светлой и тёмной. Тёмную доводим до премиума под референсы:
  глубокие поверхности, тонкие бордеры, лёгкое свечение акцентов — через
  существующие `.dark`-токены, без новых цветов.

## Затрагиваемые файлы

- Правим: `DashboardShell.tsx`, `DashboardTopBar.tsx`, `DashboardSidebar.tsx`,
  `DashboardBottomNav.tsx`, `dashboard/nav` (только группировка/метаданные, не
  роутинг), возможно `app/globals.css` (утилиты шелла/motion).
- Добавляем: `components/dashboard/PageHeader.tsx`; при необходимости —
  воркспейс-карточка (`WorkspaceCard.tsx`) и/или расширение
  dashboard-примитивов.

## Проверка (verification)

- `npm run build` (`next build`) проходит без ошибок и типах.
- `npm run lint` без новых ошибок.
- Скриншоты дашборда в **светлой и тёмной** теме через `scripts/screenshot.mjs`
  — визуальная сверка иерархии/ритма.
- Ручная проверка: при `prefers-reduced-motion: reduce` mount-переход и
  hover-анимации не проигрываются.
- Мобайл: bottom-nav и рабочая зона без горизонтального оверфлоу; CTA/воркспейс
  сайдбара скрыты на мобиле (сайдбар и так `lg:block`).
