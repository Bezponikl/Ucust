# UCust — доводка внутреннего интерфейса (дашборд) до marketing-grade

**Дата:** 2026-07-10
**Статус:** утверждён к реализации
**Ветка:** `dashboard-polish` (от `07cfcf9`)

## Контекст

Дашборд уже реализован по всем разделам (Обзор, Контент+календарь, Создать, Входящие, Отзывы, Акции, Аналитика, настройки бизнеса/аккаунта, шелл). Задача — не строить заново, а **довести до качества, при котором любой скриншот экрана можно сразу класть в рекламную кампанию** (marketing-grade), закрыв при этом пункты внешнего аудита по внутреннему интерфейсу (раздел 10, экраны 10–14) и добавив живой визуал и анимации.

Основа — аудит (`Аудит сайта.docx`, раздел 10). Каждый пункт заземлён в текущем коде (часть уже частично решена — фиксируется точно).

Демо-бизнес для съёмки — «Кофейня "Тёплый день"» (`seedDemoProject`). Реальные фото уже лежат в `public/content/` (interior, drinks, barista, latteart, beans, pastry, croissants, avatar-marina) и подключены в данных постов — инфраструктура под живой контент есть.

**Работа делится на 6 треков; реализация поэтапная (1–4 → 5 → 6), чтобы смотреть результат по фазам.**

## Глобальные принципы
- Не ломать существующую функциональность; следовать текущим паттернам и токенам.
- Русская копия — verbatim; цвета — только токены, без сырых hex.
- Анимации: 150–300ms, только `transform`/`opacity`, осмысленные (не декор ради декора), уважать `prefers-reduced-motion` (ui-ux-pro-max §7).
- Гоча проекта: не ветвить SSR-разметку по `useReducedMotion` (hydration mismatch) — для reduced-motion предпочитать CSS `@media (prefers-reduced-motion)` или client-only-безопасные приёмы.
- Верификация: `npx tsc --noEmit` + Playwright визуал на dev (демо-вход → /dashboard). **Не** запускать `npm run build` при активном dev-сервере. Git-коммит после каждой задачи. Не деплоить.

## Трек 1 — Единый `StatCard` (ядро; аудит 10.1, 10.2)

**Проблема (заземлено):** три разные реализации «карточки со статистикой»:
- `overview/StatCards.tsx` — с иконкой в цветном квадрате + value+delta+label+hint (аудит хвалит этот вариант как эталон).
- `analytics/AnalyticsView.tsx` (METRICS) — без иконки: label+value+delta.
- `promos/PromosView.tsx` (плашки статусов) — цветная цифра + label, без иконки.

**Решение:** новый компонент `components/dashboard/StatCard.tsx` — единый, на основе эталонного (с иконкой).
- Пропсы: `{ icon: IconName; value: string; label: string; tone: StatTone; delta?: string; deltaTone?: DeltaTone; hint?: string }`.
- `StatTone = "brand" | "purple" | "pink" | "orange" | "success" | "warning" | "muted"` (карта фона иконки + текста, расширяет текущий `BG`).
- `DeltaTone = "success" | "warning" | "muted"` (по умолчанию success).
- Применить в трёх местах: `StatCards` (Обзор), `AnalyticsView` METRICS (добавятся иконки+tone), `PromosView` плашки (добавятся иконки+tone).
- Данные при необходимости дополнить полями `icon`/`tone` (METRICS в `lib/dashboard/analytics.ts`, счётчики промо).

**Приёмка:** одна карточка-компонент используется на всех трёх экранах; вид консистентный (иконка → число → дельта → лейбл).

## Трек 2 — Цвет = смысл (аудит 10.3, 10.8)

**10.3 — карточка «Отзывы / требуют внимания».** Сейчас `StatCards` берёт `color`/`delta` из данных; карточка отзывов оформлена нейтрально, хотя по смыслу требует действия.
- Решение: карточке отзывов дать `deltaTone: "warning"` (янтарный) для подписи «Требуют внимания» — статус-кодирование срочности. Использовать warning-токен (из брендбука; если в `globals.css` нет — добавить `--warning` из брендбука или использовать `brand-orange` как янтарный, решить при реализации).

**10.8 — Акции: разная метрика в идентичном слоте.** Промо-карточки рендерят `metricValue`/`metricLabel` из данных; у «Запланирована» это `—` / «Охват анонса» вместо «Использований» — риск ложного прочтения.
- Решение: привести к единому лейблу «Использований» для всех карточек; для статусов без данных показывать приглушённое `—` (tone muted), визуально отличая, что это «ещё нет данных», а не иная метрика. (Правка данных `lib/dashboard/promos.ts` + рендер.)

**Приёмка:** карточка отзывов янтарная; во всех промо-карточках одинаковый лейбл метрики, «нет данных» читается как пусто, а не как чужая цифра.

## Трек 3 — Читаемость данных (аудит 10.9, 10.5)

**10.9 — график без числовых значений по оси Y.** `overview/ReachChart.tsx` (общий для Обзора и Аналитики) рисует 3 горизонтальные линии сетки, но **без подписей значений**.
- Решение: добавить лёгкие числовые подписи у линий сетки (0 / середина / максимум), формат через существующий `fmt()`. Не перегружать (ui-ux-pro-max §10 `axis-labels`).

**10.5 — статусы постов без легенды.** На «Контенте» у карточек постов цветные точки статуса (published/scheduled) без пояснения.
- Решение: добавить компактную легенду статусов рядом с фильтрами/заголовком (точка + подпись: «Опубликовано», «Запланировано», «Черновик») и/или подпись статуса текстом на карточке. Заземлить точные статусы в `ContentView.tsx` при реализации.

**Приёмка:** на графике видны опорные значения оси Y; статусы постов однозначно считываются без наведения.

## Трек 4 — UX-мелочи (аудит 10.4, 10.6, 10.7)

**10.4 — обрезка названия проекта.** `ProjectSwitcher.tsx`: триггер `max-w-[220px] sm:max-w-[240px]` + `truncate`.
- Решение: расширить до `sm:max-w-[280px]` (и проверить, что длинные названия всё же не ломают шапку). Обрезка только для реально длинных имён.

**10.6 — переразмеренные пустые слоты планирования.** Пустые карточки-слоты («+ Запланировать») той же фиксированной высоты, что заполненные.
- Решение: высота слота по контенту (компактнее пустой), либо единый аккуратный «add-slot» меньшей высоты. Заземлить в `ContentView.tsx`/`schedule.tsx`.

**10.7 — рейтинг во Входящих теряется.** `InboxView.tsx`: у отзывов `Stars` 12px в ряду метаданных (source + kind + time) — не выделяется среди диалоговых сообщений.
- Решение: для элементов-отзывов усилить рейтинг — крупнее звёзды и/или вынести числовой рейтинг заметным акцентом; карточка отзыва визуально отличается от карточки сообщения.

**Приёмка:** название проекта не обрезается без нужды; пустые слоты не «раздуты»; отзывы во Входящих читаются как отзывы с первого взгляда.

## Трек 5 — Marketing-grade визуал (живой контент под съёмку)

Основа есть (фото постов в `public/content/`). Задача — устранить оставшиеся «пустые»/заглушечные места и поднять лоск, чтобы скриншоты выглядели как готовая реклама.
- **Заполнить оставшиеся дыры:** аватары авторов во Входящих/отзывах (сейчас буква в кружке) → аккуратные аватары; любые серые/градиент-заглушки на месте медиа → реальные фото. Точечно догенерировать недостающие изображения через ИИ (skill `claude-image-generation`) под нишу кофейни (кофе, выпечка, витрины, портреты-аватары), положить в `public/content/`.
- **Дефолтные состояния — полные и красивые:** при заходе экран не показывает «выберите слева»/пустые списки как первый кадр — по возможности предвыбран показательный элемент (напр. во Входящих — выбран отзыв с ответом ИИ), чтобы скриншот был насыщенным.
- **Визуальная глубина:** акцентные мягкие градиенты/тени на ключевых карточках (обзор, графики), консистентные hover-состояния, аккуратные отступы и радиусы, микро-детали (иконки статусов, бейджи каналов). Без перегруза — в духе текущего дизайн-языка.

**Приёмка:** на любом экране дашборда (демо-данные) нет пустых серых слотов и «заглушечных» состояний; экран выглядит как готовый рекламный кадр.

## Трек 6 — Анимации и переходы

Framer-motion уже в проекте. Добавить живость (для скриншотов и видео/gif рекламы), с уважением к reduced-motion.
- **Переходы между разделами дашборда:** плавная смена контента при навигации по сайдбару (fade/slide-up контента) — через `app/dashboard/template.tsx` с motion или обёртку контента.
- **Появление карточек:** stagger fade-up для сеток статов/карточек при входе на экран (как `Reveal` на лендинге, но для дашборда).
- **Микро-анимации:** hover-lift карточек, плавные переключения табов (индикатор), анимация модалок от источника, count-up ключевых чисел (StatCard/график) при появлении.
- **Дисциплина:** 150–300ms, transform/opacity, `prefers-reduced-motion` отключает/смягчает; не ломать гидратацию (не ветвить SSR-разметку по `useReducedMotion`).

**Приёмка:** переходы между разделами и появление контента плавные; при `prefers-reduced-motion` анимации смягчены; нет дёрганья/скачков layout.
