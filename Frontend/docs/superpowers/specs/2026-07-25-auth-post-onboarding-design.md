# Дизайн: восстановление пароля, окно поста, редактируемый онбординг

Дата: 2026-07-25. Статус: утверждено. Всё — фронт/мок, без бэкенда.

## 1. Восстановление пароля (мок-флоу, стиль как у регистрации)

Зеркалит существующий `signup` (тоже мок, без реальной отправки писем).

Роуты на `AuthPageChrome`:
- `/forgot-password` — форма ввода email. На submit: `sessionStorage["uc_reset_email"] = email`, `router.push("/forgot-password/check-email")`.
- `/forgot-password/check-email` — экран «письмо отправлено» (читает `uc_reset_email`), авто-редирект через 3с на reset + кнопка «Открыть письмо сейчас» + ссылка «← Изменить email». Зеркало `signup/verify-email`.
- `/forgot-password/reset` — новый пароль + повтор (`PasswordInput`, `required`). Валидация: оба заполнены, длина ≥ 8, совпадение. Ошибки — через `toast`. На успех — локальный success-стейт: галочка, «Пароль обновлён», кнопка «Войти» → `/login`.

Правка: `/login` кнопку «Забыли пароль?» переключить с `toast(...)` на `router.push("/forgot-password")`.

## 2. Пост — полноэкранное окно вместо модалки

`PostModal` переделать из центрированной карточки в полноэкранное окно:
- Контейнер `fixed inset-0 z-[70]`, окно на весь экран на всех брейкпоинтах (не центрированная карточка).
- Своя шапка: заголовок «Редактирование поста», кнопка ✕ (закрыть). Контент — прокрутка внутри. Футер с действиями (существующие Сохранить/…).
- Состояние `editing: Post | null` остаётся в `ContentView` (URL не меняется). `onOpen={setEditing}` без изменений.
- Сохранить: Escape закрывает, лок скролла `body`, анимация входа.
- Вся текущая логика (ИИ-регенерация, тон/длина, медиа, расписание, save) — без изменений, меняется только оболочка/раскладка.
- День-модалку календаря (`ContentView`, `selected`) не трогаем.

## 3. Онбординг — все поля ревью редактируемые

Проблема: секции ревью используют `<TextInput defaultValue=.../>` (uncontrolled, без `onChange` → правки не персистятся), а массивы (конкуренты, SWOT, цели, тон) показаны статикой.

- `OnboardingProvider`: добавить `updateProfile(patch: Partial<BrandProfile>)` → `setProfile(prev => prev ? {...prev, ...patch} : prev)`. Персист уже есть (effect сохраняет `profile`).
- 5 секций (`SectionAbout/Market/Swot/Services/Goals`): все поля → контролируемые, привязаны к `profile`, пишут через `updateProfile`.
- Массивы редактируются как списки строк (add/remove/edit) — переиспользовать/добавить простой редактор списка (chips или textarea со строками). Вложенные объекты (`market`, `swot`) обновляются иммутабельно.
- Правки подхватываются дашбордом (он читает тот же `profile` из хранилища).

## Порядок реализации
1. Роуты восстановления пароля (изолировано).
2. Онбординг: провайдер + секции.
3. `PostModal` → полноэкранное окно.

Проверка каждой: `tsc`, live через Playwright (мобилка 375 + десктоп), затем прод-деплой.
