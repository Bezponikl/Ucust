# UCust — расширение контент-контейнера 1200 → 1320px

**Дата:** 2026-07-09
**Статус:** утверждён к реализации
**Ветка:** `widen-container` (от `3acb5f3`)

## Контекст

Контент-контейнер лендинга и внутренних страниц узкий: на экране 1440×900 остаётся ~110px пустых полей с каждой стороны. Цель — расширить рабочее пространство на всех страницах, чтобы (а) сетки (тарифы, фичи, дашборд) стали просторнее и (б) в будущем в hero комфортно лёг двухколоночный макет «текст слева + мокап интерфейса справа».

Ширина управляется одной CSS-переменной `--container-page` (`app/globals.css`), которую используют 20+ мест через `max-w-(--container-page)` — на лендинге, страницах about/legal, в дашборде и онбординге. Правка переменной применяется ко всем страницам сразу.

Текущие значения:
- база `:root`: `1200px`
- `@media (min-width: 2200px)`: `1400px`
- `@media (min-width: 3400px)`: `1650px`

## Решение

Поднять базовую ширину до **1320px** (выбор пользователя). Заметно шире (+120px), но на 1440 остаются поля ~50px с каждой стороны, а на Full HD (1920) — не растянуто.

### Изменения

1. **`app/globals.css` — ширина контейнера**
   - `:root { --container-page: 1200px }` → `1320px`
   - `@media (min-width: 2200px)`: `1400px` → `1480px`
   - `@media (min-width: 3400px)`: `1650px` → `1800px`
   - (Брейкпоинты подняты пропорционально, чтобы 2K/4K тоже были консистентно просторнее.)

2. **`components/Faq.tsx` — защита читаемости**
   - Аккордеон FAQ растянут на всю ширину контейнера; на 1320 строки ответов станут слишком длинными (UX-правило: ≤~75 символов в строке).
   - Ограничить ширину блока аккордеона центрированным `max-w-4xl` (заголовок секции уже защищён внутри `SectionHeading`).

3. **`components/FinalCta.tsx` — проверка**
   - Убедиться, что текстовый блок финального CTA не растягивается на всю ширину; если тянется — ограничить точечно (`max-w-*`). Правка только при фактической необходимости.

### Что НЕ трогаем (осознанно)

- **`SectionHeading.tsx`** — заголовки (`max-w-2xl/3xl`) и подзаголовки (`max-w-xl`) уже ограничены собственной шириной. Тексты секций не изменятся.
- **`Hero.tsx`** — структуру НЕ меняем. Остаётся центрированным (текст `max-w-xl`). Двухколоночный hero с мокапом интерфейса — **отдельная будущая задача**; сейчас только освобождаем пространство.
- **about/legal-контент** — `app/about/page.tsx` и `app/legal/[slug]/page.tsx` уже используют `max-w-3xl` для текста статей; расширение контейнера их не тронет (шире станет только шапка).
- **Сетки** (тарифы, фичи-карусель, каналы, ProductShowcase, HowItWorks, StatBand, дашборд, онбординг, футер) — специально не трогаем: они автоматически станут просторнее, это и есть цель.

## Вне объёма

- Перестройка hero в двухколоночный макет и вставка мокапа интерфейса — отдельный будущий проект.
- Изменение кегля/типографики, отступов секций, сеток — не входит (только ширина контейнера + защита читаемости).

## Верификация

1. `npx tsc --noEmit` — без ошибок.
2. `npm run build` — сборка проходит.
3. Визуальный обход (Playwright) на 1440×900: нет горизонтального скролла; поля контейнера ~50px; сетки шире; тексты секций/hero/about/legal не растянулись; FAQ-ответы читаемы (ограничены).
4. Проверка мобилки (375) и планшета (768): без изменений (контейнер и так ограничен вьюпортом минус поля).
5. Не деплоить; прод не трогаем.
